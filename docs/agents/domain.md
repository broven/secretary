# Domain Docs

This repository uses a single domain context.

Before exploring or changing the codebase:

1. Read the root `CONTEXT.md`.
2. Read relevant decisions under `docs/adr/`.
3. Use the glossary's canonical vocabulary in code, tests, issues, and docs.
4. Surface conflicts with an existing ADR instead of silently overriding it.

Missing domain documentation is not itself an error. Create or update it only
when domain terminology or an architectural decision is actually resolved.
